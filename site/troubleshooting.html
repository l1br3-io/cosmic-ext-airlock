Troubleshooting

  • Every shortcut reset to defaults right after installing (0.1.0). Airlock 0.1.0 wrote its extra bindings with a keysym form COSMIC rejects (key: Some(..) instead of key: "grave"), so cosmic-comp discarded the whole custom shortcuts file and ran factory defaults; that file holds all your customizations, so everything looked reset. Nothing was deleted: your entries are still on disk, and either fix restores them immediately, no re-login:
    • airlock install --uninstall puts your file back byte-exactly, or
    • upgrade to 0.1.1 and re-run airlock install; it replaces 0.1.0's malformed entries and leaves yours untouched.
    The one exception: a save in Settings → Shortcuts while the session showed defaults overwrote the file with what the screen showed.
  • Alt+Tab does nothing. The first press starts the daemon (about 340 ms when cold); press again. If it persists, airlock list names any missing protocol; check that ~/.cargo/bin is on your session PATH.
  • Another tool fights over WindowSwitcher. The user-level override is one slot; last writer wins. Re-run airlock install to take it back; --uninstall then restores whatever Airlock itself backed up.
  • Alt+` (the key above Tab) or Alt+Esc dead after install. The key was already bound; install skipped it and said so in its output. Free it in Settings → Input → Keyboard → Shortcuts → Custom, then re-run airlock install.
  • After logout or a compositor crash. The daemon exits by design; the next press spawns a fresh one, and a stale socket self-heals.
  • Overlay sticks. A 30 s hard deadline always releases the grab; if the overlay still stays up: pkill -x airlock, then press Alt+Tab to restart clean.

Every release build goes through the hardware verification checklist; if something behaves differently on your machine, that checklist tells you what to report.
